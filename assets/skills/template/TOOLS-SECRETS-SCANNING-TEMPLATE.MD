## Usage Instructions
1. This report is automatically generated by the impm-tools-secrets-scanning skill, covering project files including source code, configuration files, environment files, and deployment scripts.
2. Risk level for each finding:
   - **High**: Hardcoded passwords/private keys/AK/SK and other plaintext credentials that can directly lead to unauthorized access;
   - **Medium**: Internal IPs, database connection strings containing credentials, .env files being tracked, and other indirect risks;
   - **Low**: High-entropy strings, example credentials in comments, low-risk configurations etc.
3. Each finding must include file path (with line number), matched content summary (anonymized), and remediation suggestion.

## 5. Remediation Priority
### High Risk (Must Remediate Immediately)
- Migrate hardcoded credentials to environment variables or a secret management service (e.g., Vault, AWS Secrets Manager)
- Rotate leaked keys/passwords/tokens
- Remove leaked files from git history (git filter-branch / BFG)

### Medium Risk (Recommended to Remediate Soon)
- Add .env files to .gitignore and remove from tracking
- Replace passwords in database connection strings with environment variable injection
- Replace internal IP addresses with domain names or service discovery mechanisms

### Low Risk (Recommended for Improvement)
- Remove example credentials from comments or replace with placeholders
- Manually verify high-entropy strings; if not keys, add exclusion comments
