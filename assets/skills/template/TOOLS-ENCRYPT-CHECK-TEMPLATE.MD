# Cryptographic Algorithm Compliance Check Report
**Project Name**: **Check Date**: **Checker**: TL **Tool Basis**: impm-tools-encrypt-check automated scanning (based on the "Cryptography Law of the People's Republic of China", GB/T 39786-2021 "Basic Requirements for Cryptographic Applications in Information Systems" cryptographic assessment standard)

## Usage Instructions
1. This report is automatically generated by the impm-tools-encrypt-check skill, covering source code, encryption/security-related utility classes, and algorithm parameters in configuration files.
2. Risk level for each finding:
   - **High**: Weak algorithms (MD5/SHA-1/DES/3DES/RC4/RC2 etc.) used in password storage, data encryption, signature, random number generation for keys, and other security scenarios; use of deprecated insecure algorithms.
   - **Medium**: Weak algorithms used in semi-security/transition scenarios, or overly short keys (RSA-1024); insufficient domestic cryptography coverage used in critical security scenarios.
   - **Low**: Weak algorithms used in clearly non-security scenarios (file checksums, deduplication hashes, cache keys) with no security impact.
   - **Notice**: International strong algorithms (AES/RSA-2048/SHA-256) used as transitional solutions but replaceable with domestic cryptography; SM1/SM9 require hardware support; no domestic cryptography algorithms found in the project.
3. Each finding must include file path (with line number), algorithm call code snippet, usage scenario analysis, and remediation suggestions. Mechanical classification by algorithm name is prohibited.

## 6. Remediation Priority
### High Risk (Must Remediate Immediately)
- Prohibit use of MD5/SHA-1 for password storage, message signing, and other security scenarios; use SM3 or bcrypt/scrypt/Argon2/PBKDF2 (for passwords) and SM3 (for signatures).
- Prohibit use of DES/3DES/RC4 and other weak symmetric encryption to protect data; use SM4.
- Prohibit use of RSA-1024 and other overly short keys; use SM2 or RSA-2048+.
- Prohibit use of Math.random()/random() in security scenarios to generate keys, IVs, salt values, or Tokens; use CSPRNG.

### Medium Risk (Recommended to Remediate Soon)
- Gradually replace weak algorithms introduced in transitional scenarios such as SHA-1 fingerprint verification and certificate verification with SM3/SHA-256.
- When domestic cryptography is not used in critical security scenarios, perform domestic cryptography transformation per cryptographic assessment requirements.

### Low Risk (Recommended for Improvement)
- MD5/SHA-1 in non-security scenarios (file checksums, deduplication hashes, cache keys) may be retained, but it is recommended to add comments explaining the usage scenario.
- For projects using strong algorithms (AES/SHA-256/RSA-2048) as transitional solutions, gradually replace with domestic cryptography (SM4/SM3/SM2).
