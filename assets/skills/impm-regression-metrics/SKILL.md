# impm-regression-metrics Skill

## Trigger Words
quality metrics, defect density, defect removal efficiency, DRE, test coverage, fix rate, severity distribution, review issue statistics, regression-metrics, regression quality

## When to Use
Use in Phase 4, after the code review (impm-coding-review) completes and before the version wrap-up, when the code review-type quality metrics need to be backfilled into the regression.md quality metrics report generated in Phase 1 by impm-regression-test. This skill is Phase 2 of the quality metrics and, together with Phase 1 of impm-regression-test, constitutes the complete version quality metrics report.

## Execution Steps
### Step 1: Read the review report and the Phase 1 regression quality report
1. Call impm_doc_reader (docType=review, target=version) to read the current version code review report docs/{Project Abbreviation}-v{Current Version Number}/{Project Abbreviation}-review.md.
2. Call impm_doc_reader (docType=regression, target=version) to read the current version quality metrics report docs/{Project Abbreviation}-v{Current Version Number}/regression.md (Phase 1 generated by impm-regression-test).
3. If the review report is missing, state that the code review was not executed in this version, report honestly and skip the backfill (mark the review-type metrics as "not executed"), and still enter step 6 to record progress.

### Step 2: Count the number of review issues and their severity distribution
1. Count the total number of issues by category from the "Issue list" of the review report (3.1 security vulnerabilities / 3.2 performance traps / 3.3 code quality / 3.4 architecture compliance / 3.5 test coverage).
2. Aggregate the "severity" of all issues (high/medium/low), and output the severity distribution statistics.
3. Aggregate the "fix status" of all issues, and count the number fixed / number not fixed.

### Step 3: Calculate the fix rate and the defect quality metrics
1. Fix rate = number of fixed issues / total number of review issues × 100%.
2. Defect density: choose a basis and state it:
   - Optional basis 1 (by code size): defect density = total number of review issues / the scale of this change's code (KLOC or lines of newly added code, if easy to obtain);
   - Optional basis 2 (by requirements size): defect density = total number of review issues / the total number of requirements/user stories in this version.
   Pick one of the two and state the basis in the report, so it can be compared across versions.
3. Defect removal efficiency DRE (Defect Removal Efficiency): DRE = number of removed (fixed) defects / total number of defects found × 100%; calculate with the total number of review issues as the total number of defects found and the fixed number as the removed number.
4. Test coverage: Phase 1 has already written it based on requirement/user story case coverage or tool coverage; if the review report has a test coverage assessment conclusion, it may be supplemented for explanation.

### Step 4: Backfill the review quality metrics sections of regression.md
1. Based on the calculation results of steps 2/3, backfill into regression.md in the format of chapters 3~5 of REGRESSION-TEMPLATE.MD:
   - 3.1 code review issue statistics (severity distribution table + fix rate);
   - 3.2 defect density;
   - 3.3 defect removal efficiency DRE;
   - 4 compliance determination (determine, item by item, whether the quantitative targets are met/not met by combining the Phase 1 test metrics);
   - 5 conclusion and suggestions (including the explanation of unmet items, handling suggestions for remaining unfixed issues, and cross-version comparison reference).
2. Keep the existing content already written in Phase 1, such as "1, 2, 3.x test metrics", only supplement/update the review quality metrics and conclusion sections; do not overwrite or delete the Phase 1 content.
3. Call impm_doc_writer (docType=regression, target=version, expectedBase=the latest full text read in step 1.2) to overwrite the complete regression.md.
4. Verify that regression.md has been backfilled with the review quality metrics and the content is correct.

### Step 5: Record progress
1. Call impm_progress add (impm-regression-metrics, completed) to record this skill's completion status in version_progress.md.
2. Verify that this step status has been recorded in version_progress.md.
