# opencode-impm —— I am the Project Manager (AI Project Manager)

> An OpenCode-based, engineering-grade full-lifecycle development suite: with the "AI Project Manager" at its core, it orchestrates professional AI subagents through a waterfall workflow (Initialization → Requirements Analysis → Coding Development → Regression Testing and Version Documentation) to complete the entire software development lifecycle.

---

## Introduction

opencode-impm is an OpenCode plugin suite that includes:

- **13 professional AI Agents**: uniformly dispatched by the PM (Project Manager); BA / SA / TL / DBA / TE / SCM / DW / CS / WS / FEE / BEE / SSE each play their part.
- **46 Skills and 46 Commands**: each waterfall step corresponds to one skill and one command, executed strictly in order — no skipping, no out-of-order execution, no parallelism.
- **11 Plugin Tools**: document read/write, version management, progress management, task scheduling, context building, project analysis, git operations, etc., invoked by the skills.
- **10 standard document templates**: URS / PRD / SAD / DBD / API / LLD / TESTCASE / TASK / REVIEW / PROJECT, ensuring a uniform document structure.

## Core Features

- **Waterfall workflow orchestration**: four phases in a fixed order; after each step the status is recorded in the version progress table (version_progress.md), so progress can be verified at any time.
- **Test-driven development (TDD)**: test cases are written before coding; tests are written and executed after coding, and code is committed only when everything passes.
- **Version-based management**: each version corresponds to a version directory `docs/{project abbreviation}-v{version}/` and a git branch `{project abbreviation}-v{version}`.
- **Streamlined context passing**: each coding task receives only streamlined context (task information + user story + project information + relevant architecture sections).
- **All-English output**: all documents, comments, and reports are written in English.

## Environment Requirements

- Node.js >= 18
- OpenCode (a version that supports plugins, skills, and commands)

## Installation

Method 1: local installation (recommended for development/debugging)

```bash
npm install          # postinstall automatically runs the install script
# or run it manually:
node scripts/install.mjs
```

Method 2: install into a target project as an npm dependency

```bash
npm install opencode-impm
```

The install script copies the agents, commands, and skills under `assets/` into the target project's `.opencode/` directory, and copies the compiled plugin into `.opencode/plugins/impm/` (OpenCode automatically loads local plugins at startup).

You can also specify an installation target:

```bash
node scripts/install.mjs --target /path/to/project
```

Restart OpenCode after installation to use the `/impm` command.

## Quick Start

In OpenCode, enter:

```
/impm
```

The PM Agent advances through the four phases in order:

| Phase | Orchestrating command | Description |
| --- | --- | --- |
| Phase 1: Initialization | `/impm-init` | Initialize the project: determine the project type, create the version directory and progress table, generate the initial URS/PRD/SAD/DBD/API/LLD/task list/test case documents, and commit |
| Phase 2: Requirements Analysis | `/impm-docs` | Confirm the requirements for the current version: create the version branch and version directory, generate URS/PRD, update SAD, generate DBD/API/LLD, create the task list, and commit |
| Phase 3: Coding Development | `/impm-coding` | Loop through the tasks: collect context → code search → web search → database/API design → test cases → coding → write tests → run tests → commit, until all tasks are complete |
| Phase 4: Regression Testing and Version Documentation | `/impm-finish` | Regression tests, code comments, code review, project map update, document merging, update readme/agent/deployment documents, merge the main branch |

You can also run a single step command, e.g., `/impm-init-urs`, `/impm-prd-create`, `/impm-task-coding-code`, etc.

| `/impm-init-project` | Generate the project basic information docs/project.md |
| `/impm-init-version` | Create the version directory and the version progress table |
| `/impm-init-urs` | Generate the User Requirement Specification |
| `/impm-init-prd` | Generate the Product Requirement Document |
| `/impm-init-sad` | Generate the System Architecture Design document |

| `/impm-init-lld` | Generate the Low-Level Design document |
| `/impm-init-task` | Generate the task list (task JSON) |
| `/impm-init-testcase` | Generate the test case document |
| `/impm-init-commit` | Commit all deliverables of the initialization phase |

### Phase 2: Requirements Analysis (impm-docs series)

## Standard Document Paths

| Document | Path |
| --- | --- |
| Project basic information | `docs/project.md` |
| System architecture design | `docs/sad.md` |
| Version directory | `docs/{project abbreviation}-v{version}/` |
| Version requirement/design documents | `docs/{abbreviation}-v{version}/{abbreviation}-{urs\|prd\|dbd\|api\|lld\|testcase}-v{version}.md` |
| Database scripts | `docs/{abbreviation}-v{version}/{abbreviation}-dbd-v{version}.sql` |
| Task list | `docs/{abbreviation}-v{version}/{abbreviation}-task-v{version}.json` |
| Version progress table | `docs/{abbreviation}-v{version}/version_progress.md` |
| Task directory | `docs/{abbreviation}-v{version}/task_{task id}/` (context.md, cs.md, ws.md, testcase.md) |
| API test scripts | `scripts/API-TEST/{abbreviation}-api-test-v{version}.py` |
| Build/deployment plan | `deploy/build.md`, `deploy/deploy.md` |
| Project documentation | Root `readme.md`, `agent.md` |
